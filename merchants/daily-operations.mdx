## Finding a transaction

The portal lists transactions newest first. You can filter by:

- Status
- Date range

Each transaction shows its identifier, amount, masked customer mobile number,
status, and the time it was created.

## Transaction statuses

| Status | Meaning | Have you been paid? |
|---|---|---|
| Awaiting code | The customer has not yet entered their code | No. Do not release goods. |
| Authorised | The customer's wallet has been debited | Yes. Safe to fulfil. |
| Cleared | The debit has cleared and is awaiting settlement | Yes. |
| Settled | Included in a payout to your bank | Yes, and paid out. |
| Reversed | The transaction was voided; value returned to the customer | No. |
| Failed or expired | The payment did not complete. No money moved. | No. |

<Note>
**Authorised** is the point at which it is safe to hand over goods or services.
You do not need to wait for **Cleared** or **Settled**.
</Note>

## What to tell a customer

| Situation | What to say |
|---|---|
| Code not received | Confirm the mobile number is the one registered with Cashd. Codes are limited to three per number every 15 minutes. |
| Wrong code entered | Three attempts are allowed. After that, start a new payment. |
| Code expired | Codes are valid for three minutes. Start a new payment. |
| Insufficient balance | The customer's Cashd balance does not cover the amount. Offer another payment method for the difference, or reduce the amount. |
| No Cashd account | The number is not registered with Cashd, or the customer has never topped up. Offer another payment method. |

Never ask a customer to read their code aloud in a way others can hear, and never
record it.
