Cashd provides two integration options against the Merchant API v1. Both use the
same credentials, settlement stream, and reporting. The difference is who hosts
the payment step.

<CardGroup cols={2}>
  <Card title="Web Checkout" icon="browser" href="/integration/web-checkout/overview">
    Cashd hosts the payment page. You create a session, send the customer there,
    and read the outcome. Two server calls.
  </Card>
  <Card title="Direct API" icon="terminal" href="/integration/direct-api/overview">
    You host the payment step and handle the one-time code yourself. Four calls.
  </Card>
</CardGroup>

## Choosing

| Condition | Option |
|---|---|
| A browser or in-app webview is available at the payment step | Web Checkout |
| You are funding a customer wallet or store credit | Web Checkout |
| No browser or webview is available | Direct API |
| Physical till, kiosk, or call centre | Direct API |
| The payment interface must stay in your own product | Direct API |

You can run both on one merchant account.

## Two rules that apply to both options

1. **Fulfil on a transaction read, never on a redirect, a webhook, or a single
   synchronous response.** See
   [Transaction states](/integration/concepts/transaction-states).
2. **Run a reconciliation process.** Any journey can be interrupted after the
   wallet is debited. Without reconciliation you lose those transactions.
