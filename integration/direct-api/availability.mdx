---
title: "Availability"
description: "POST /merchant/availability"
---

Evaluates whether a customer's Cashd balance covers an amount. Nothing changes,
no code is sent, nothing is charged. Use it to decide whether to offer Cashd.

```http
POST {base}/api/v1/merchant/availability
Authorization: Bearer tc_live_sk_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
Content-Type: application/json

{ "phone": "+966501234567", "amount_halalas": 20000 }
```

```http
200 OK

{
  "status": "available_partial",
  "requested_halala": 20000,
  "authorizable_halala": 12500,
  "shortfall_halala": 7500,
  "confirmation_expires_at": null
}
```

## Outcomes

| `status` | Meaning | Action |
|---|---|---|
| `available_full` | The full amount is coverable | Proceed with the requested amount |
| `available_partial` | Part is coverable | Apply your partial-coverage policy below |
| `unavailable` | No spendable balance | Do not offer Cashd. Show the message for the returned `reason` |

When `status` is `unavailable`, `reason` is one of `no_account`, `no_balance`,
`account_locked`, or `issuer_unhealthy`.

## Partial coverage

`authorizable_halala` is what you can charge. `shortfall_halala` is what you must
collect another way.

| Policy | Behaviour |
|---|---|
| Split tender | Collect `shortfall_halala` by card or cash, then create the transaction for `authorizable_halala` only |
| All-or-nothing | Offer Cashd only when `status` is `available_full` |

<Warning>
If you split, create the transaction for `authorizable_halala`, not for the
original amount. Sending the original amount fails with
[`insufficient_balance`](/integration/errors/insufficient_balance).
</Warning>

## Availability is not a reservation

The response reflects a moment in time. Balance can move between this call and
the charge, and another transaction can consume it. An
[`insufficient_balance`](/integration/errors/insufficient_balance) on the
subsequent create is a normal outcome, not an exception — handle it in the flow.

## What is not returned

No balance figure, no programme names, no indication of how the customer's
balance was funded. You learn only whether the amount you asked about is
coverable.

## Limits that can make an amount unavailable

A customer's spending is subject to limits set by Cashd, including a per-consumer
daily cap. An amount within the customer's balance can still be unavailable
because of them. Treat `unavailable` and
[`insufficient_balance`](/integration/errors/insufficient_balance) as ordinary
outcomes and offer another tender.
