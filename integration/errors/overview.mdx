title: "Error handling"
description: "The error envelope, the four classes, and how to handle each."
---

Every `4xx` and `5xx` response uses one shape.

```json
{
  "error": {
    "code": "insufficient_balance",
    "message_en": "The customer's balance is too low for this charge.",
    "message_ar": "رصيد العميل غير كافٍ لهذه العملية.",
    "doc_url": "https://docs.trycashd.com/errors/insufficient_balance",
    "request_id": "req_01HW..."
  }
}
```

| Field | Use |
|---|---|
| `code` | Branch on this. Stable for the life of the major version |
| `message_en`, `message_ar` | Display to the customer or staff, matching locale |
| `doc_url` | The page for that code in this section |
| `request_id` | Log it. Quote it in support requests |

<Warning>
Branch on `code`, never on message text. Messages are copy and change without
notice; codes do not.
</Warning>

## Classes

| Class | Statuses | Handling |
|---|---|---|
| Business | `422` | Show the localised message. Offer another tender. Do not retry |
| Upstream | `502`, `503`, `504` | Retry once, then fall back. For `authorization_unknown` and `adapter_timeout`, read the transaction instead |
| Rate limit | `429` | Exponential backoff with jitter, from 500 ms, capped at 30 s |
| Caller | `400`, `401`, `403`, `409`, `404` | Fix the request or the credential. Never retry unchanged |

<Warning>
Never retry a `422`. The request will be rejected identically, and on code-entry
paths it consumes the customer's attempt allowance.
</Warning>

## When the outcome is unknown

[`authorization_unknown`](/integration/errors/authorization_unknown) and
[`adapter_timeout`](/integration/errors/adapter_timeout) do not mean the charge
failed. The wallet may have been debited.

Read `GET /merchant/transactions/:id` and act on the returned status. Do not
create a second transaction for the same intent.
