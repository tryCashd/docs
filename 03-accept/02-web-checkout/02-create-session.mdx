---
title: "Create a session"
description: "POST /merchant/checkout_sessions"
---

Create the session from your backend. Your merchant key must never reach the
client.

```http
POST {base}/api/v1/merchant/checkout_sessions
Authorization: Bearer tc_live_sk_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
X-Idempotency-Key: order_01J8ZP4K2N
Content-Type: application/json
Accept-Language: ar

{
  "amount": 10000,
  "reference": "order_01J8ZP4K2N",
  "phone": "+966501234567",
  "locale": "sa-ar",
  "expires_in_minutes": 15,
  "redirect_urls": {
    "success": "https://links.example.sa/cashd/return?ref=order_01J8ZP4K2N",
    "failure": "https://links.example.sa/cashd/return?ref=order_01J8ZP4K2N",
    "cancel":  "https://links.example.sa/cashd/return?ref=order_01J8ZP4K2N"
  }
}
```

```http
201 Created

{
  "session_token": "tc_live_cs_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx",
  "checkout_url": "https://{checkout-host}/sa-ar/c/tc_live_cs_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx",
  "expires_at": "2026-08-09T21:15:00Z"
}
```

## Fields

| Field | Required | Notes |
|---|---|---|
| `amount` | Yes | Integer halala. Fixed at creation and server-authoritative — the customer cannot change it on the hosted page. Omit only in the [open-amount variant](/03-accept/02-web-checkout/05-open-amount). |
| `reference` | Yes in practice | Your own order or intent identifier, unique per intent. This is how you resolve the outcome. |
| `redirect_urls` | Yes | `success`, `failure`, and `cancel` are all required. Each host must be pre-registered with Cashd. |
| `phone` | No | Pre-fills the hosted page. Send it when you know it. |
| `locale` | No | `sa-ar` or `sa-en`. Defaults to `sa-ar`. The returned `checkout_url` already carries it. |
| `expires_in_minutes` | No | Defaults to 30, clamped to between 3 and 1440. |

## Return URLs

All three URLs are required, or the request is rejected. Sending the same URL for
all three is acceptable — you determine the outcome by reading, not by which URL
fired.

Every host must be on the allow-list Cashd registered for you during account
setup. A merchant with no registered hosts cannot create a session.

## Before you open the page

Persist a record containing at least:

- `reference`
- Your idempotency key
- The amount
- A state of your own, such as `awaiting`

You need this record to reconcile.

## Session behaviour

| Property | Detail |
|---|---|
| Single use | One session binds at most one transaction. Concurrent or retried attempts cannot produce a second debit. |
| Token | `session_token` is returned once. You do not need to store it — everything afterwards is keyed on `reference`. |
| Expiry | After `expires_at` the session can no longer bind a transaction. |

## Errors

| Code | Cause |
|---|---|
| [`validation_failed`](/errors/validation_failed) | Missing or partial `redirect_urls`, an unregistered host, no checkout configuration, or an invalid amount |
| [`unauthorized`](/errors/unauthorized) | Key missing, revoked, or from the wrong environment |
| [`merchant_inactive`](/errors/merchant_inactive) | Merchant account suspended |
