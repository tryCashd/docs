This call is the authority on what happened. Fulfil on its response.

```http
GET {base}/api/v1/merchant/transactions/by_reference?reference=order_01J8ZP4K2N
Authorization: Bearer tc_live_sk_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

## Not completed

```http
200 OK

{
  "reference": "order_01J8ZP4K2N",
  "status": "pending",
  "amount": 10000,
  "expires_at": "2026-08-09T21:15:00Z"
}
```

## Completed

```http
200 OK

{
  "public_id": "txn_0f8c2d1e-4a7b-4c3f-9e21-6b5a8c7d0e11",
  "status": "authorized",
  "amount": 10000,
  "consumer_phone_masked": "+9665•••••567",
  "void_reason": null,
  "created_at": "2026-08-09T21:02:11Z",
  "expires_at": null
}
```

## How to branch

| Response | Meaning | Action |
|---|---|---|
| `status: pending` | The session exists but no transaction is bound yet | Do not fulfil. Let reconciliation retry. |
| `status: expired` | The session lifetime elapsed with nothing bound | Terminal. Do not fulfil. |
| A transaction object | A transaction is bound | Branch on its `status` below. |
| `404` | The reference is unknown to Cashd | Terminal. Investigate — you may have sent a reference that was never used to create a session. |

| Transaction `status` | Action |
|---|---|
| `authorized` | **Fulfil.** The wallet has been debited. |
| `redeemed` | **Fulfil** if you have not already. Cleared. |
| `pending_otp` | Still in progress. Do not fulfil. |
| `failed`, `expired` | Terminal. No money moved. Do not fulfil. |
| `reversed` | Voided. Do not fulfil; reverse it if you already did. |

## Fulfil exactly once

Your return handler, your reconciliation process, and any webhook handler can all
act on the same transaction at the same time.

Put a unique constraint on the Cashd transaction identifier in the table where you
record fulfilment.

```sql
CREATE UNIQUE INDEX idx_fulfilment_cashd_txn
  ON fulfilments (cashd_transaction_id);
```

Exactly one writer wins. Without this, a single transaction can be fulfilled two
or three times.

## Repeated references

If the same `reference` was used for more than one session, the bound session
takes precedence over any later unbound one. Use a unique reference per intent to
avoid the situation entirely.
