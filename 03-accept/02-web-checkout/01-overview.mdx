You create a session from your backend, send the customer to a Cashd-hosted page,
and read the outcome when they return.

```
Your backend            Cashd hosted page          Cashd
     │ 1. create session ──────────────────────────►  │
     │ ◄──────────── checkout URL + session token ────┤
     │ 2. open URL in browser or webview              │
     │                        │ phone + code ──────►  │
     │ ◄──── 3. redirect to your return URL ──────────┤
     │ 4. read the transaction ────────────────────►  │
     ▼
  fulfil
```

## What Cashd handles

Phone entry, code delivery and verification, resend control, attempt limits,
expiry, bilingual error messages, and right-to-left layout.

## What you build

| Step | Page |
|---|---|
| Create a session | [Create a session](/03-accept/02-web-checkout/02-create-session) |
| Send the customer and get them back | [Return handling](/03-accept/02-web-checkout/03-return-handling) |
| Determine what happened | [Resolve the outcome](/03-accept/02-web-checkout/04-resolve-outcome) |
| Catch interrupted journeys | [Reconciliation](/02-concepts/03-recovering-outcomes) |

If the customer should choose the amount on the Cashd page rather than in your
interface, see [Open amount](/03-accept/02-web-checkout/05-open-amount).

## Sequence

| # | Actor | Call |
|---|---|---|
| 1 | Your backend | `POST /merchant/checkout_sessions` |
| 2 | Your frontend | Open `checkout_url` |
| 3 | Cashd | Redirect to your success, failure, or cancel URL |
| 4 | Your backend | `GET /merchant/transactions/by_reference` |
