## Money

All money fields are integers in halala, named `*_halalas`.

```
1 SAR = 100 halala
SAR 125.00 = 12500
```

<Warning>
Do not represent money as a floating-point value anywhere in your integration.
Rounding drift surfaces at settlement, months later.
</Warning>

## Consumer identifier

A Saudi mobile number. `+9665XXXXXXXX` is canonical and always safe.

| Accepted | Example |
|---|---|
| E.164 | `+966501234567` |
| International without `+` | `966501234567` |
| International with `00` | `00966501234567` |
| Local | `0501234567` |
| Subscriber only | `501234567` |

Whitespace and dashes are stripped. Cashd normalises server-side, so a consumer
who registered as `0501234567` is found by `+966501234567`.

Non-Saudi numbers, landlines, and anything that does not reduce to a nine-digit
subscriber number starting with `5` are rejected.

## Transaction identifiers

Transactions carry a `public_id` of the form `txn_<uuid>`. Endpoints accept
either the prefixed form or the bare identifier.

## Timestamps

ISO 8601, UTC. Example: `2026-08-09T21:02:11Z`.

## Language

Send `Accept-Language: ar` or `Accept-Language: en`. Every error carries both
`message_en` and `message_ar`. Render the one matching your customer's locale,
with right-to-left layout for Arabic.

## Versioning

The API is URL-versioned at `/api/v1`. Breaking changes are issued under a new
major version, and existing routes remain supported for a defined transition
period.

## Transport

TLS 1.2 minimum, TLS 1.3 preferred.
